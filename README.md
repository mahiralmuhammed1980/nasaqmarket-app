# نسق فارما

تطبيق أندرويد (هاتف وتابلت، واجهة متجاوبة عربية RTL) لإدارة صيدلية مستقلة. **كل البيانات على الجهاز نفسه** (SQLite)، مع نسخ احتياطي واستعادة عبر Google Drive الخاص بالزبون.

- لا خادم لديك بعد التفعيل: الاتصال الوحيد بك هو **تفعيل أول مرة** (تسجيل الدخول بـ Google + التحقق من قائمة الإيميلات المسموحة).
- جهاز واحد لكل ترخيص: التفعيل على جهاز جديد بنفس الإيميل **ينقل الترخيص تلقائياً** (حد أقصى 3 عمليات نقل كل 30 يوماً).
- التحديث: يفحص التطبيق `version.json` على GitHub Releases، ينزّل الـ APK ويثبّته فوق القديم **بدون فقدان البيانات**.

## الميزات
لوحة التحكم • **الصندوق** (دخل وخرج بوسائل نقد/بطاقة/حوالة، مصاريف، سحب وإيداع المالك، إغلاق يومي) • **كشف حساب المورد** (رصيد افتتاحي + مشتريات - دفعات، مع PDF) • **الشركات** وربط الأدوية بها • **الأدوية المقيّدة بوصفة** (بيانات الوصفة والطبيب والمريض والرقم الوطني إلزامية عند البيع + سجل للمراجعة) • المخزون والدفعات وتواريخ الصلاحية (الخصم بنظام الأقرب انتهاءً أولاً FEFO) • مسح الباركود بالكاميرا (يدعم GS1 DataMatrix: يعبّئ رقم الدفعة والانتهاء تلقائياً) • الفواتير (PDF عربي، مشاركة، طباعة، دفع جزئي، إلغاء مع إرجاع الكميات) • الموردون وأوامر الشراء والاستلام • استيراد كتالوج الأدوية والشركات (Excel/CSV) دون أي تأثير على المخزون والمالية • استيراد الجرد • تصدير CSV • نسخ احتياطي (Drive يومي تلقائي + ملف محلي) • قفل PIN • شعار الصيدلية.

## الإعداد لأول مرة (مرة واحدة منك)

### 1) Firebase
1. أنشئ مشروعاً في [Firebase Console](https://console.firebase.google.com) وأضف تطبيق **Android** بحزمة `com.nasaq.pharma`.
2. أضف **بصمة SHA-1** لمفتاح التوقيع (انظر قسم المفتاح) من *Project settings → Your apps*.
3. فعّل **Authentication → Sign-in method → Google**.
4. فعّل **Firestore Database** (وضع الإنتاج) ثم الصق محتوى [`firebase/firestore.rules`](firebase/firestore.rules) في تبويب *Rules* وانشره.
5. نزّل `google-services.json` (للـ CI، يُرمَّز base64 كسر؛ لا يُرفع إلى المستودع).
6. من *Authentication → Google → Web SDK configuration* انسخ **Web client ID** → سر `GOOGLE_SERVER_CLIENT_ID`.

### 2) Google Cloud (Drive)
في نفس المشروع على [Google Cloud Console](https://console.cloud.google.com): فعّل **Google Drive API**، واضبط *OAuth consent screen*. التطبيق يطلب النطاق `drive.appdata` فقط (مجلد مخفي خاص بالتطبيق)، وهو نطاق غير حساس فلا يحتاج مراجعة Google. في وضع *Testing* أضف إيميلات الزبائن كـ Test users، أو انشر التطبيق (Publish) ليعمل مع الجميع.

### 3) إضافة زبون جديد (بعد البيع)
في Firestore أنشئ مجموعة `allowed` ومستنداً **معرّفه هو إيميل الزبون بأحرف صغيرة** (مثال `customer@gmail.com`)، والحقول اختيارية. هذا كل شيء: يفعّل الزبون التطبيق بنفسه، ويُنشأ مستند `licenses/{email}` تلقائياً.
- سحب الصلاحية قبل التفعيل: احذف مستند `allowed`.
- تصفير عدّاد النقل لزبون تجاوز الحد: عدّل `licenses/{email}.transferCount` إلى 0.
- بعد التفعيل يعمل التطبيق دون اتصال بك؛ لا يمكن سحب ترخيص مفعّل (قرارك: بيع لمرة واحدة).

### 4) مفتاح التوقيع (مهم جداً)
```bash
keytool -genkey -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias nasaq
keytool -list -v -keystore release.jks -alias nasaq   # لنسخ SHA-1 إلى Firebase
```
**احتفظ بنسخة من `release.jks` وكلمة مروره في أكثر من مكان.** إن ضاع المفتاح فلن يتمكن أي تحديث من التثبيت فوق النسخة القديمة (سيضطر الزبون لإلغاء التثبيت وفقدان البيانات المحلية).

### 5) أسرار GitHub (Settings → Secrets → Actions)
| السر | القيمة |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 release.jks` |
| `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD` | بيانات المفتاح |
| `GOOGLE_SERVICES_JSON_BASE64` | `base64 -w0 google-services.json` |
| `GOOGLE_SERVER_CLIENT_ID` | Web client ID من الخطوة 1.6 |
| `LICENSE_SECRET` | نص عشوائي طويل لتوقيع الرخصة المحلية |

### 6) صفحة التطبيق وسياسة الخصوصية (لشاشة موافقة Google)
الملفات في `firebase/public/` (`index.html` و`privacy.html`). قبل النشر استبدل `CONTACT_EMAIL` في `privacy.html` ببريد الدعم. ثم:
```bash
npm install -g firebase-tools
firebase login
cd firebase
firebase deploy --only hosting --project <معرّف مشروعك>
```
تصبح الصفحتان على `https://<معرّف مشروعك>.firebaseapp.com` و`/privacy.html`، فتستخدمهما في *OAuth consent screen ← Branding*.

## إصدار نسخة وتحديث الزبائن
1. ارفع `version` في `pubspec.yaml` (مثال `1.0.1+2`؛ الرقم بعد `+` يجب أن يزيد دائماً).
2. من GitHub: *Actions → Release APK → Run workflow* (أو ادفع وسماً `v1.0.1-2`).
3. ينشر الـ Workflow على *Releases*: `nasaq_pharma.apk` و`version.json` (يحتوي رقم الإصدار والرابط وبصمة SHA-256).
4. عند فتح التطبيق عند الزبون يجد التحديث، ينسخ احتياطياً محلياً، ينزّل الـ APK ويثبّته؛ البيانات تبقى (نفس `applicationId` ونفس التوقيع). ترحيل المخطط (`kSchemaVersion` في `lib/data/database.dart`) يعمل تلقائياً عند أول فتح.

> ملف `version.json` يُقرأ بلا تسجيل دخول، لذا يجب أن يكون المستودع **عاماً**، أو استضف الملفين في مكان عام آخر وغيّر `UPDATE_URL` في `release.yml`.

## أول تثبيت عند الزبون
حمّل `nasaq_pharma.apk` من صفحة Releases وثبّته (يطلب الهاتف السماح بالتثبيت من مصدر غير معروف مرة واحدة). ثم: تسجيل الدخول بـ Google ← (اختيارياً) ربط النسخ الاحتياطي في *البيانات → Google Drive* ← تفعيل PIN من *الإعدادات*.

## ملفات الاستيراد
القوالب متوفرة داخل التطبيق: *البيانات → قالب كتالوج الأدوية / قالب الجرد*. الأعمدة العربية أو الإنجليزية، CSV (UTF-8) أو xlsx. الاستيراد يعرض **معاينة** (جديد/تحديث/أخطاء) قبل الاعتماد، ويحفظ نسخة أمان تلقائياً.
- **كتالوج الأدوية**: يحدّث جدولَي الأدوية والشركات المرجعيين فقط. المطابقة بالباركود أولاً ثم الاسم التجاري + العلمي. لا يحذف شيئاً غائباً عن الملف، ولا يمسّ الأصناف والدفعات والفواتير والمشتريات والأرصدة.
- **الجرد**: ينشئ الأصناف الجديدة ويضيف الدفعات؛ لا يغيّر أسعار الأصناف الموجودة.

## التطوير
```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # عند تعديل lib/data/tables.dart
flutter analyze && flutter test
flutter run --dart-define=DEV_BYPASS_LICENSE=true            # تجاوز التفعيل في وضع debug فقط
```
البنية: `lib/data` (جداول drift والمستودع والاستيراد) • `lib/services` (ترخيص، PIN، Drive، تحديثات، PDF) • `lib/ui` (الشاشات) • `firebase/` (قواعد Firestore).

## حدود معروفة
- قاعدة البيانات غير مشفّرة على القرص (محمية بحماية نظام أندرويد للتطبيقات؛ النسخ الاحتياطي على Drive داخل مجلد التطبيق المخفي).
- الترخيص المحلي موقّع لكنه لا يصمد أمام تعديل متخصص للـ APK؛ هدفه منع النسخ العادي بين الأجهزة.
- الجهاز القديم بعد نقل الترخيص يبقى يعمل دون اتصال (لا فحص بعد التفعيل، بحسب القرار).
- لا تزامن حي بين الأجهزة: نسخ واستعادة فقط.
